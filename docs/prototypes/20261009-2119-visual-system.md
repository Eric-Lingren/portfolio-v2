# Prototype: Visual system for the fly-through

## Question

Which palette pairing (sketch → polished), accent and type pairing make the fly-through look best?

The handoff matrix was 3 pairings x 2 accents x 2 type pairings (12 combos). It was judged on three surfaces: the hero panel with its load-time build wipe, the Selected work panel with 4 cards and real demo screenshots, and a flat case study excerpt (about 300 words) to test long-form reading. The sketch and polished layers had to align pixel for pixel: same fonts and sizes, with only color, background and border style allowed to differ.

## Verdict

**G "Cyber Hearth": cool paper blueprint → velvet obsidian, coral + cyan dual accent, Geist + Geist Mono.**

It replaces the seed's "proposed defaults" note. It is a dark-only theme, which matches the decision to defer the light/dark toggle.

### Tokens

```css
/* polished layer: 60 / 30 / 10 */
--po-bg:            #0c0a0e;  /* 60% velvet obsidian: page, stage, panels */
--po-surface:       #111827;  /* 30% deep tech blue (gray-900): cards, pillars, case meta, pull quote */
--po-ink:           #f9fafb;  /* headings and body */
--po-muted:         #9ca3af;  /* secondary text (7.0:1 on surface) */
--po-border:        #252a36;
--po-border-strong: #3a4150;  /* ghost-button outline fallback */

/* 10% accents, split by role */
--accent:     #ff5a36;  /* coral, "people": 6.4:1 on bg, 5.7:1 on surface */
--accent-2:   #06b6d4;  /* cyan, "tech":    8.1:1 on bg, 7.3:1 on surface */
--on-accent:  #0c0a0e;  /* text on coral fills, 6.4:1 (white fails at 3.2:1) */

/* sketch layer: cool paper blueprint */
--sk-bg:    #eff1f4;
--sk-line:  #1f2937;               /* dashed borders, image X boxes (13:1) */
--sk-ink:   #111827;               /* wireframe text */
--sk-grid:  rgba(31, 41, 55, .11); /* 24px grid */
--sk-hatch: rgba(8, 145, 178, .28);/* cyan hatching inside image placeholders */
--accent-ink-sk: #bd4328;          /* redline notes; raw coral is only 2.7:1 on the paper */
```

### Where each accent goes

| Coral `#ff5a36` (people) | Cyan `#06b6d4` (tech) |
|---|---|
| Eyebrow `FRONTEND-FIRST FULL-STACK ENGINEER` | Panel component tags (`<Hero /> · z 0px`) |
| "View work" button fill (obsidian text) | Email button: cyan outline + cyan text |
| Case study pull-quote rule | Proof links, "Read case study", inline case-study links |
| Redline notes in the sketch layer (`#bd4328`) | Card hover: cyan border + glow |
| Dither band on the build line | Hatching inside sketch image boxes |

- **Build line:** a coral → cyan horizontal gradient (`linear-gradient(90deg, #ff5a36, #06b6d4)`) with a coral glow (`0 0 18px 2px #ff5a3699`). The 1-bit dither band under it stays coral.
- **Card hover:** `border-color: #06b6d4; box-shadow: 0 0 0 1px #06b6d4, 0 0 28px color-mix(in srgb, #06b6d4 40%, transparent)` with a 0.2s transition. Polished layer only.
- **Type:** Geist for headings (600, `letter-spacing: -0.035em`) and body. Geist Mono for the eyebrow (500, 13px, `+0.14em`), tags, kickers, meta and notes. The hero name is `clamp(52px, 10vw, 136px)` on two lines with `line-height: 0.92`. Case study body is 18px / 1.68 in a 720px column.

### Constraints to carry forward

- **Layout parity:** both layers render the same markup. Theme CSS may change only color, background, border color and border style. Border widths stay identical (1.5px in both, solid vs dashed). Any rule that changes layout must hit both layers.
- **Accent text is computed, not assumed.** Every accent-on-background pair was checked against 4.5:1. Coral needs a darker ink on the paper sketch. Both accents pass unchanged on obsidian and on the gray-900 surface.
- **Wipe method:** use the transform-only wipe, not a per-frame `clip-path`. It held 60fps at 99% smooth on Eric's phone. See the PRD Handoff Notes.
- **Light demo screenshots** stand out hard on the obsidian cards. That reads as intentional "proof" and was kept.

## Explorations

- **Original 12-combo matrix** (pairings A/B/C x redline/lime x Geist/Instrument Serif), on one static page switched with `?p=&a=&t=`, a floating bar, and an on-screen FPS meter.
- **Lime on light pairings** fails as text (about 1.2:1). Darkening it gives olive. A "vivid" variant kept full saturation at a relaxed 3:1. It looked more lime but sat below AA for small text.
- **Electric blue `#2962ff`** was added at Eric's request. It clashed with pairing B's deep-blue sketch, as the handoff predicted. On dark it read poorly until a lighter text tint (`#7fa1ff`, 7.8:1) was used.
- **Shortlist round:** #5 (A · electric blue · Geist) and #31 (slate midnight + navy + terracotta `#e07a5f`, a 60/30/10 split Eric proposed).
- **E: slate + warm teal `#14b8a6`.** The best single-accent contrast (7.2:1), but teal was the weakest on the paper sketch.
- **F: warm obsidian + amber hearth `#f59e0b`** with a matching parchment and umber sketch. It was the most cohesive warm option.
- **Matching sketch layers:** after #31 and F, each finalist got its own sketch palette, instead of all sharing pairing A's blue blueprint. This made each build read as one theme.
- **H, Neon Fusion:** G's palette plus gradient name text, a `//` eyebrow, 8px buttons, 25% hover glows and chip kickers. It was the loudest option, and gradient name text reads like a common Tailwind template.
- **Phone check:** the first live meter showed running totals since load, which were hard to read. It was replaced with a one-tap scripted sweep that compares both wipe methods. See the PRD Handoff Notes for results.
- **Performance (desktop Chrome, 120Hz):** every combo held 118 to 124fps through the fly-through, with 0 jank frames over 25ms once loaded. Worst frames were 9 to 18ms. The only long frames, 3 of them with a worst of 375ms, came during the first page load and font fetch.

## Rejected Paths

- **Instrument Serif headings:** Geist + Geist Mono won on every finalist.
- **Pairing B, dark blueprint → light:** blue accents disappear into the blue sketch mid-wipe.
- **Pairing C, paper sketch → warm light:** lime needs a contrast compromise. No finalist used a light polished layer.
- **Redline `#ff4b1f` and acid lime:** dropped at the shortlist.
- **#5 electric blue, #31 terracotta, E teal, F amber:** finalists that lost to G.
- **H Neon Fusion styling:** too loud, and the gradient name looks like a template. G keeps the same colors without it.
- **Copy and structure from the pasted palette specs:** a slogan headline, "foster culture" subtitle, "Let's Build Together" / GitHub buttons, a culture/mentorship section, an "Available for Teams" pill, and invented skills. These conflict with the seed: the eyebrow and name are locked, the line is parked, the CTAs are "View work" + email, and the 7 panels are fixed.
- **Dark sketch → dark polished:** not tried. It was already rejected in the handoff because it hides the wipe.

## PRD Handoff Notes

- **Phone 60fps passes on a scripted sweep.** On Eric's phone, an 8-second sweep (top → bottom → top, 3 panels, G theme) gave these results:

  | Wipe method | fps | Frames ≤ 20ms | Worst frame | Frames > 25ms |
  |---|---|---|---|---|
  | `clip-path: inset()` written per frame | 59 | 99% | 50ms | 3 |
  | transform-only (`translateY` on an `overflow: hidden` box, counter-translated inner) | 60 | 99% | 33ms | 3 |

  **Use the transform-only wipe.** It avoids a repaint each frame and had the shorter worst-case hitch:

  ```js
  // outer clip box moves down, inner content moves back up by the same amount
  clip.style.transform  = `translateY(${built * h}px)`
  inner.style.transform = `translateY(${-built * h}px)`
  line.style.transform  = dither.style.transform = `translateY(${built * h}px)`
  ```

- **Real finger scrolling was rougher than the sweep.** Eric's live readings dipped to about 43fps during touch scrolling. The sweep doesn't reproduce iOS momentum scrolling or Safari's address bar collapsing, which fires `resize`. The prototype re-measured every panel (`offsetHeight`) and reset the `vh`-based spacer on each resize. The build should use stable viewport units (`svh`/`lvh`), avoid layout reads on scroll-driven resizes, and repeat the phone check with real touch input. The full 7-panel page is also untested; the prototype had 3 panels.
- **Accent legibility is still open.** Eric approved the G palette but flagged that the coral and cyan accent text is still slightly hard to read. It is less legible than he wants, even though both pass 4.5:1 (coral 6.4:1, cyan 8.1:1 on obsidian). This was deferred on purpose, not resolved in the prototype. Options for the PRD: brighter text-only tints of each accent (as done for electric blue, `#7fa1ff`), a heavier weight or larger size for small accent text such as the 11 to 13px mono eyebrow, tags and links, or accent fills with dark text in place of accent-colored text.
- **Dual accent density.** On the hero, the coral eyebrow, coral button and cyan email button sit close together, so G reads busier than the single-accent options. The PRD should keep the role mapping strict: coral = people and conversion, cyan = tech and navigation. No third accent color.
- **Case study readability on G was not reviewed by eye.** It was only checked for rendering. Confirm the 18px body in `#f9fafb` on `#0c0a0e` doesn't glare during the first case-study build.
- **Touch has no hover.** The cyan card glow is a desktop-only flourish. Decide whether tap gives any feedback.
- **OG image:** the accepted default (name, eyebrow, half-wireframe and half-polished hero) should use G: the cool paper sketch on one side, obsidian on the other, and the coral → cyan build line on the split.
- **Seed updates for /to-seed:** set the visual system to G (tokens above). Remove the "dark/blueprint mode toggle not confirmed" note. Fold in the other post-seed decisions listed in `docs/handoffs/20261009-2118-visual-system-prototype.md`.
